# Word 批量转换与快速更新计划（O-06）

更新：2026-10-09。只保留当前工作和顺序；执行证据见 [宿主记录](real-host-acceptance.md)。

## 已有基础

加载项已有批量入口与裸 LaTeX 选区入口；扫描后确认再写入，不必返回应用另找功能。
Word 文档选择、部分 LaTeX→SVG/PNG/OLE 与本应用 OMML↔OLE 路线已实现。
转换弹窗已居中、正文独立滚动、底部操作可见，支持空白处/Esc 取消。
计划内准确 LaTeX 缓存已实现，仍保留每个对象独立 ID、范围与原文校验。
批次内重复 OMML 模板复用、屏幕状态恢复与非空段清理保护已完成；已有固定混合 Word 样例及原生转换对比。
原生行内批次已改为显式 Range 写入，避免逐条移动选区；回滚绑定目标文档并清除对应清单。
原生行内批次已有清单逐条追加/回读试点，保留旧条目与扩展，失败保留原文；性能未达标，默认不启用。
新桌面程序已包含上下文淡字补全，但 NativeOffice/安装器尚未统一到同源载荷。

以上不表示综合性能、安装版全链路和所有宿主格式已完成。

## 约束与依赖

- 当前安装版 VSTO 因开发证书根信任不足加载失败；不自动写入用户根证书存储。
- 真实 Word 扫描后的 OS 前台切换仍开放，浏览器或 WebView2 命令获准不能代替该闭环。
- 文档索引不得复用过期/移动/重复对象；提交前再次校验目标文档与修订。
- COM 写入保持串行；缓存或批次失败不能导致整个文档静默丢失。
- 普通批量扫描只处理明确数学定界符；裸 LaTeX 使用选区入口，不猜测正文。
- 原生 Word 可选择文档；Office.js 绑定其任务窗格宿主，不宣称跨文档任意控制。
- 无源元数据公式标记为重建；第三方 MathType/MTEF 仍按 Core 有限只读路线推进。
- 第三方 OLE/图片先提取明确关联的源码；Word 类身份门禁与 Core 声明式源码探测已有，载体/UI 仍需接通，见 [读取边界](foreign-source-read-boundary.md)。
- MTEF raw 去重/诊断、独立有限 AST 读取及有界语义批次复用已有；补宿主提取和正式接入，结构指纹不复用不同参数的结果，第三方写回单独验收。
- VSTO 是加载项技术，不是公式格式；新 OLE 插入与原位转换按宿主支持分别提供。
- 文档修改仍需要确认；“加载项内直接启动”不等于跳过确认或自动覆盖原文。
